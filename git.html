GitHub & Git

Differences between GitHub and Git

GitHub - a cloud-based platform that hosts Git repositories that stores your code remotely, allows you to collaborate with others and share your projects publicly or privately.

Git - a version control system that tracks changes in files over time and increases the workflow by saving and comparing committed version control, undoing mistakes, and collaborating safely.

Why Using Git is important?

Using Git in a structured way:

  • Protects your work from accidental loss
  • Creates a transparent research and development history
  • Supports reproducibility and collaboration
This workflow is widely used in both academic research and software development and now you can do it, too!

First Time Set Up

To start using Git and GitHub, first you need to configure your identity and authenticate your personal computer. Here is the step-by-step guide how to set up the whole system on your own.

1. Create Your GitHub Account

Go to GitHub website and following the instructions there set up your first ever account.

If you already have an account and would want to use that one throughtout the whole process, you can skip this step.

2. Configure Your Git Identity

Git uses your name and email to label commits so choose the name that you want others to identify you by while collaborating on projects. 


      git config --global user.name "[Name]"
      git config --global user.email "[email@example.com]"
      git config --list
The last command verifies if your configuration was succesful.

3. Check for an Existing SSH Key

SSH keys allow secure communication between your computer and GitHub without entering your password each time. 


      ls -al ~/.ssh
If you see files like id_ed25519 and id_ed25519.pub, you already have an SSH key and can skip to step 5.

4. Generate a New SSH Key

If you don't have an SSH key, generate a new one using the command below. 


      ssh-keygen -t ed25519 -C "your-email@example.com"

5. Copy the SSH Public Key

Dispaly the public key with the command below and copy the whole output. 


      cat ~/.ssh/id_ed25519.pub
If you have any trouble finding your key try this command instead:
pbcopy < ~/.ssh/id_ed25519.pub

6. Add the SSH Key to GitHub

To complete this step go to your GitHub Account Settings and navigate to SSH and GPG keys section. Once there, click New SSH key and paste your copied key. Save your changes to connect your computer to your account.

7. Final Connection Test

If you have successfully set up your connection, you’ll see a message confirming authentication with the command below. 


      ssh -T git@github.com

Git Commands

Common Git Workflow

Now we will go through a common Git Workflow, strating with getting access to your online repository and ending with commiting and saving your new changes.

1. Access your repository

Once you have created your working repository on your GitHub Account you can access it on your computer through the link you find on your project main page.
Go: [Your repository] -> Code (Green Button) -> SSH -> [Copy the link]

1. If your connecting with your repository for the first time use command #1
2. If you are accesing it once again any next time to update any changed files use command #2 

      #1 git clone git@github.com:username/repository-name.git
      #2 git pull

2. Move Into the Project Directory and Edit Your Files

Navigate into your project folder. Each file you have in your online GitHub repository should be found there as well.

Remember: All Git commands must be run inside the repository directory. 

      cd repository-name

3. Stage Changes

Staging is a phase when you tell Git which files you would like to keep track of and commit at the end of your work.

Staging Commands
#1 Add this one file to Staging
#2 Add all changed files to Staging
#3 Remove this one file from Staging 

      #1 git add filename
      #2 git add .
      #3 git reset filename
Check Status
To check which files were added into Staging phase use the command below. 

      git status

4. Commit Changes

Commits are the snapshots of what you have changed while working on your project. It saves all files you added during Staging. While commiting your work you should always add a message that describes what and why you have changed something. 


      git commit -m "My message"
Remeber: Detailed commits are always better than none!

5. Push Changes to GitHub

To save all the changes you committed along side with your message, you need to upload them to GitHub using the command below. This updates the online version of your project. 


      git push

Congratulations! You just successfully used Git and improved the quality of your whole project!

Additional Useful Commands

Branches

Branches are seperate duplicates of your work that allow you to test out new features or do some experiments without affecting the main code. They guarantee safe space for development and testing, as well as parallel work before saving the changes and merging them back into the main branch.

Branches Commands
#1 display all branches
#2 create a new branch
#3 go to and work on the given branch
#4 compare two branches
#5 merge the chosen branch with the current one
#6 save changes from the chosen branch 

    #1 git branch
    #2 git branch 'branch_name'
    #3 git checkout 'branch_name'
    #4 git diff 'branch_1'..'branch_2'
    #5 git merge 'branch_1'
    #6 git push origin 'branch'

Other Useful Commands

Here you can find the list of other common commands that you may use while working on your projects.

#1 Create a new Git repository in the current directory when starting a new project
#2 Move or rename a file while preserving its Git history
#3 Delete the file and stage the removal for the next commit
#4 Display the commit history, showing past changes and messages
#5 Show differences between files that have been modified but not yet committed 

    #1 git init
    #2 git mv old_name new_name
    #3 git rm filename
    #4 git log
    #5 git diff
